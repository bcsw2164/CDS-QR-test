# Credit 페이지 / 저장 카드 미리보기

## `credit/` — 이름 목록 + 현장 사진

`data/qr_name.json`의 이름을 순서대로 나열하고, 그 뒤쪽 레이어에 현장 사진을 듬성듬성 흑백으로 깔아둔다. `#photo-layer`(사진)가 뒤, `#credit-names`(이름)가 그 위에 겹치고 두 레이어 모두 JS가 채운다.

### 사진 추가 방법
`credit/images/onsite/01.jpg`, `02.jpg`, ... 형식으로 번호를 이어 저장하고 `script.js`의 `PHOTO_COUNT`를 사진 장수에 맞게 올린다.

### 첫 화면 사진 로딩

세 곳이 맞물려 있다.

1. **`index.html`의 `<link rel="preload" as="image">` 3장** — 사진 배치(`layoutPhotos`)는 이름 JSON을 받아 화면에 뿌린 뒤에야 시작하므로, 그냥 두면 사진 요청이 그만큼 늦게 출발한다. 미리 걸어두면 HTML을 읽는 순간부터 받기 시작해 `<img>`가 만들어질 때 이미 캐시에 있다. **`EAGER_COUNT`와 장수를 맞출 것.**
2. **`EAGER_COUNT = 3`** — 첫 화면 근처에 놓이는 장수. 사진은 위에서부터 차례로 배치되므로 앞 번호가 곧 첫 화면이다.
3. **[중요] `loading`·`decoding`·`fetchPriority`는 반드시 `src`보다 먼저 정한다.** 브라우저는 `src`가 정해지는 순간 그 시점의 `loading` 값으로 "지금 받을지 미룰지"를 결정해 버린다. 예전 코드는 `src`를 먼저 주고 뒤이어 `loading='lazy'`를 붙였는데, 그때는 이미 늦어서 lazy가 무시되고 21장(약 9MB)이 한꺼번에 내려받기 큐에 들어갔다. 연결 수가 한정돼 있으니 서로 밀려 첫 화면 사진마저 늦게 떴다 — **"크레딧 사진이 초기에 잘 안 뜬다"의 원인.**

### 사진 배치 (`layoutPhotos`)

- **세로**: 전체 높이를 사진 장수만큼의 구간(`band`)으로 나누고 각 구간 안에서만 흔들어서, 한쪽에 몰리지 않고 듬성듬성 간격이 유지되게 한다. 큰 등급은 구간보다 커서 이름과 겹치는데 **그건 의도한 것이다.**
- **가로**: 좌/우를 번갈아 배치해 지그재그로 읽히게 한다. 큰 등급은 `bleed`만큼 가장자리 밖으로 밀어내 화면에서 잘리게 한다(`#photo-layer`가 `overflow: hidden`).
- 고정 시드 난수(`makeRandom(20240917)`, mulberry32)를 쓴다 — 새로고침해도 배치가 그대로 유지돼서 "매번 달라 보이는" 산만함이 없다.
- 창 폭이 바뀌면 이름 줄바꿈이 달라져 전체 높이도 달라지므로 150ms 디바운스로 다시 계산한다.

### `PHOTO_TIERS` — 사진 크기 등급

메인 페이지 스포크 그래픽처럼 대·중·소 차이를 확실하게 둔다.

```
size  : [minPx, 배수, maxPx]
jitter: 같은 등급끼리도 조금씩 달라 보이게 하는 흔들림 폭(±비율)
bleed : 화면 밖으로 삐져나가는 양(자기 폭 대비 비율). 0이면 안쪽에만 놓인다
```

`viewportUnit()`/`resolveSize()`는 About 페이지 `sketch.js`와 같은 방식이다 — 폭만 쓰면 아이패드 가로처럼 납작한 화면에서 사진이 과하게 부풀고, 아이폰 세로처럼 좁은 화면에서는 작은 등급이 손톱만 해진다. 높이×1.2와 견줘 작은 쪽을 쓰면 두 경우 모두 기준이 안정된다. `minPx`/`maxPx`가 양끝을 잠가 화면 폭 대비 비율(%)로 두던 이전 방식보다 기기별 체감 크기가 비슷해진다.

**가로로 넓은 화면(PC·아이패드 가로)에서는 네 등급 모두 `maxPx`에 걸리므로 `maxPx`끼리의 비율이 곧 그 화면의 인상이 된다.** 소를 280으로 두던 때는 특대와 1:3.4까지 벌어져 작은 사진이 혼자 겉돌아 보였다 — 소·중의 천장을 올려 1:2.4로 좁히고, 등급 간 배율도 1.4 → 1.3 → 1.3으로 고르게 맞췄다.

실제 폭(아이폰 14 세로 기준 390 / 아이패드 프로 13 가로 기준 1229):

| 등급 | 세로 | 가로 |
|---|---|---|
| 소 | 164 | 390 |
| 중 | 242 | 550 |
| 대 | 332 | 720 |
| 특대 | 449 | 950 |

사진 폭은 무대 폭의 96%로 제한한다 — 무대보다 넓어지면 답답해진다.

### 이름 hover 색
`NAME_HOVER_PALETTE`는 `shared/core.js`의 `RADIAL_COLOR_PALETTE`와 같은 5색이다. 이름마다 하나를 랜덤으로 골라 `--name-color`에 심어두면 CSS가 꺼내 쓴다.

**사진 배치와 달리 고정 시드를 쓰지 않는다** — 새로고침할 때마다 색 조합이 다시 섞이는 쪽이 200명 넘는 목록에 생기를 준다.

페이드(opacity transition)는 넣지 않는다 — 색이 즉시 바뀌어야 마퀴의 숫자 색 전환(step-end)과 같은 톤으로 읽힌다.

### CSS 조절값
`:root`의 세 개만 만지면 전체 리듬이 바뀐다.
```
--credit-gap   이름 줄 사이 간격
--credit-size  이름 글자 크기
--credit-cols  한 줄에 놓을 이름 수 (1 = 한 사람당 한 줄)
```

### 마퀴
그룹을 통째로 2번 반복해두고 트랙을 `-50%`만큼 옮기면, 두 번째 그룹이 정확히 첫 번째 그룹 자리로 들어와서 이어지는 것처럼 보인다.

`.count`의 `font-weight: inherit`은 `<b>`의 기본 굵기 대신 마퀴 글자 굵기를 따르게 하는 것이다.

### 참여 인원 숫자 색 애니메이션 (`.count` / About의 `.accent`)
`animation: ... 2.5s step-end infinite`.

**`step-end`가 핵심이다.** 기본값(ease 등)으로 두면 색이 키프레임 사이를 보간하면서 팔레트에 없는 중간색들이 지나가 "자연스럽게 번지는" 느낌이 되는데, `step-end`는 다음 키프레임 시점까지 현재 색을 그대로 붙잡고 있다가 딱 끊어 바꾼다. 그래서 팔레트 5색만 정확히 번갈아 나온다.

각 색이 머무는 시간 = duration ÷ 5. 지금은 0.5초씩이다. `100%`에 첫 색을 다시 적어 끊김 없이 반복한다.

About의 `.accent`에는 `@media (prefers-reduced-motion: reduce)`로 색을 팔레트 첫 색에 고정하는 규칙이 붙어 있다.

### 글자 위 커서
마퀴 문구·이름은 읽고 색만 바뀌는 요소라 `cursor: default`로 I빔 대신 평범한 화살표를 띄운다. About 페이지의 `.lead`·`.main-text`·`#footer`도 같다.

## `card-preview/` — 저장 카드 미리보기 (개발용)

아카이브 상세의 "저장하기"가 만들 한 장을 실제 출력 픽셀 크기 그대로 띄워 본다. 카드를 그리는 일은 전부 `shared/save-card.js`가 하므로 **여기서 보이는 그림이 곧 폰에 저장될 그림이다.**

**레이아웃을 고칠 곳은 여기가 아니라 `shared/save-card.js`의 `L` 상수다.** 이 파일은 그 함수에 넘길 재료(아이템·이름·수치·QR)를 모으고 미리보기 전용 기능(탭 전환 / 1:1 보기 / 내보내기 / 용량 비교)만 얹는다.

### 아카이브와 중복된 코드
다음은 `archive/sketch.js`에서 복사해 온 것이고, **값이 같아야 아카이브 화면과 카드의 색·회전이 일치한다.**
- `COLOR_SEED_SALT` / `ROTATION_SEED_SALT` / `GROUP_ANGLE_SEED_SALT`
- `normalizeErrorAxis` (퍼센타일 정규화)
- `buildItems` = `generateFlowerItems` + `generateRadialItems`/`generateSpokeItems`를 합친 것

### p5를 쓰는 이유
캔버스는 쓰지 않지만(`noCanvas()`) **p5 인스턴스 자체는 살아 있어야 한다** — `save-card.js`가 그래픽을 얹을 때 `createGraphics`가 필요하다.

### 웹폰트
`renderPreview()`를 두 번 부른다. 웹폰트(Wanted Sans)가 올라오기 전에 그리면 대체 폰트로 한 번 찍히므로 `document.fonts.ready` 뒤에 다시 그린다.

### 용량 비교
폭과 품질을 바꿔가며 실제로 인코딩해 보고 용량만 재서 표로 보여준다. 추정값으로 고르면 틀리기 쉬워서 자를 하나 둔 것이다. 재는 동안 그 폭으로 카드를 실제로 다시 그리므로(= 내보낼 때와 같은 경로) 표의 숫자가 곧 받게 될 파일 크기다.

```
MEASURE_WIDTHS    [810, 1080, 1350, 1620]
MEASURE_QUALITIES [0.8, 0.85, 0.9, 0.95]
```

### CSS
카드 바깥은 전부 회색(`#8a8a8a`)으로 깔아서 흰 카드의 경계가 보이게 한다. 기본은 화면 높이에 맞춰 축소하고, `#stage.actual`이면 1:1(실제 픽셀)이다.
